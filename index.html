Profile

Models I can defend in a design review

I like problems where a model has to earn its place. Every project here starts with a physical question (will it knock, will it hold boost at altitude, will it crack), then a model is built, calibrated against data, and only then used to explore.

My dissertation tied those threads together: a GT-Suite model of an ethanol-fuelled 2026 F1 cylinder, a 900-case design of experiments, and a Gaussian Process surrogate that maps knock risk in under a second per case.

How I work

Frame it, model it, prove it, then use it

The same five steps run through every project, whether the tool is GT-Suite, Ansys or a spreadsheet.

  1. Frame

    Turn the brief into a physical question with a measurable output and a constraint.

    e.g. hold 4.8 bar(A) boost at 2,200 m

  2. Model

    Build the simplest model that still contains the physics that matters.

    e.g. single cylinder + pressure boundary

  3. Calibrate

    Match it to measured or published data before trusting any trend.

    e.g. pressure trace, P–V, IMEP

  4. Explore

    Sweep, sample and fit surrogates to see the whole design space, not one point.

    e.g. 900-case Latin Hypercube

  5. Decide

    State the recommendation, its limits, and the next test that would change it.

    e.g. knock-safe spark window
